# 验证与交付

## 修改前

- 读取目标仓库的 `AGENTS.md`。
- 确认目标产品包、Starter、依赖版本和允许修改的文件。
- 对即将使用的组件核对官方文档和当前公开导出。

## 默认静态检查

- JSON、YAML、Vue、TypeScript 和配置文件结构有效。
- 导入路径与所选产品包一致，没有混用其他 Starter 的入口。
- 组件名、属性、事件和插槽没有凭空推断。
- 没有许可证、令牌、密钥、客户数据或本地绝对路径进入仓库。
- 没有复制 TechUI 源码、完整测试用例或文档站实现。

## 运行级验证

- 目标仓库已有且允许的 lint、类型检查或单元检查，可按最小相关范围执行。
- 安装依赖、构建、开发服务器、浏览器回归和真实设备验证都需要仓库规范与用户授权。
- 验证失败时保留原始错误并定位原因，不把未运行或失败的检查描述为通过。

## 结果报告

最终报告应分别列出：

1. 修改了什么以及关键文件。
2. 已执行并通过的检查。
3. 未执行的构建、浏览器、安装、发布或端到端验证。
4. 仍存在的版本、授权或外部环境风险。

如果目标是缺陷的最小复现和 Issue 文案，使用 `$techui-issue-reproducer`。
