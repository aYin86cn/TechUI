# 应用组合配方

## 常规业务应用

- 选择 `@techui/base`。
- 使用 `TuiProvider`、最小 Router 和清晰的页面布局。
- 表单、数据展示和反馈组件按用户任务组合。
- 请求、领域模型和业务状态保留在应用层，不塞入通用 UI 组件。

## 管理后台

- 需要正式 Admin 能力时选择 `@techui/admin`，并核对 `TuiAdminLayout` 与路由元信息的当前文档。
- 先实现导航、内容区和明确的加载/异常状态，再按真实需求增加菜单、权限或登录。
- 不为一个静态后台页面预置完整权限框架、动态路由协议和状态中心。

## 数据看板

- 普通数据看板可从 Base 起步；明确需要科幻视觉时选择 Scifi；已授权且确需综合能力时再评估 Prime。
- 使用 `TuiAdaptive` 时先确定设计分辨率、缩放边界和容器职责。
- 使用 `TuiEcharts` 时只在已提供实际 ECharts 对象并核对功能开关后启用。
- 用 `TuiLoaderPanel`、`TuiResult`、`TuiDigitalFlip`、`TuiRollingTable` 等表达状态和指标，数据获取仍由应用层负责。

## 科幻界面

- 选择 `@techui/scifi`，使用公开的 Scifi 面板、按钮和装饰能力。
- 装饰层不得遮挡操作、降低文字可读性或破坏响应式布局。
- 普通管理语义仍使用清晰、稳定的交互，不用科幻动效替代状态反馈。

## Prime 综合应用

- 仅在具备合法授权或明确评估条件时选择 `@techui/prime`。
- 按需求启用 Admin、ECharts 或高级能力，不一次性打开全部功能。
- 任何许可证、令牌、密钥或客户材料都不得写入仓库、示例或 Issue。

## 完成标准

- 页面覆盖加载、空态、错误和正常数据状态。
- 布局在目标尺寸范围内可用，交互元素可聚焦且语义明确。
- 组件 API 来自公开文档，业务组合没有反向污染通用组件职责。
- 验证范围和未执行项被明确报告。
