# TechUI Issue 报告

本仓库是 TechUI Base、Admin、Prime、Scifi 的统一问题入口。报告使用用户当前语言；API 名称、版本号、错误信息和代码标识符保持原样。

## 模板

```md
## 问题概述

用一到三句话说明问题及影响。

## 受影响范围

- Package: @techui/...
- Version:
- Regression: 是 / 否 / 未确认

## 环境

- OS:
- Node.js:
- Package manager:
- Browser:

## 最小复现

- Repository/path or link:
- Validation level: 静态整理 / 命令复现 / 浏览器复现 / 跨环境确认

## 复现步骤

1.
2.
3.

## 期望行为

说明公开文档或稳定契约下应发生的行为。

## 实际行为

说明实际观察到的结果。

## 日志或截图

粘贴已脱敏的最小相关内容。

## 补充信息

列出出现频率、已尝试排查项、文档差异和未执行的验证。
```

## 撰写规则

- 标题使用“包名或组件 + 可观察问题”，避免“无法使用”“有 Bug”等泛化描述。
- 步骤必须从仓库的某个 Starter 或明确的最小工程开始。
- 期望行为引用公开文档或可解释的稳定契约，不把个人偏好写成缺陷。
- 实际行为只写观察结果；原因分析放在补充信息并标记为推测。
- 日志只保留相关片段，但不要删掉错误类型、调用位置和关键上下文。
- 提交前再次检查许可证、密钥、账号、客户数据、内部域名和本地隐私路径。
- 生成报告后等待用户授权；不要自动联网创建、评论或关闭 Issue。
