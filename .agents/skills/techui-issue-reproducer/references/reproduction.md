# 最小复现方法

## 选择唯一 Starter

| 问题范围 | 首选目录 |
| --- | --- |
| 基础组件、通用布局、表单、数据展示 | `starter/base` |
| Admin 布局、菜单、后台路由 | `starter/admin` |
| Prime 独有或综合能力 | `starter/prime` |
| Scifi 动态 SVG、科幻组件、可视化界面 | `starter/scifi` |

若问题在多个包中出现，先用依赖最少、触发最稳定的包复现；在 Issue 中另列受影响范围，不复制四份复现。

## 收敛步骤

1. 记录原始现象、预期结果和触发条件。
2. 固定实际使用的 TechUI、Vue、Vite 和浏览器版本。
3. 从最匹配的 Starter 开始，只加入触发问题的组件和数据。
4. 逐项移除业务服务、状态库、请求层、权限、装饰样式和无关路由。
5. 每移除一项都确认问题仍存在；无法运行验证时不要宣称最小化已完成。
6. 把最终步骤缩减到任何维护者都能按顺序执行的程度。

## 必要证据

- 受影响产品包和精确版本。
- 操作系统、Node.js、包管理器、浏览器及版本；不相关项可省略。
- 最小复现目录或可访问链接。
- 从干净状态开始的复现步骤。
- 期望行为与实际行为。
- 完整但已脱敏的错误文本、控制台日志或截图。
- 是否每次出现、偶发出现，及已知触发边界。

## 验证等级

- **静态整理**：文件和配置已检查，但未安装、构建或打开页面。
- **命令复现**：已在明确命令下观察到失败或异常输出。
- **浏览器复现**：已在明确浏览器和交互步骤中观察到问题。
- **跨环境确认**：已在两个或更多明确环境中得到一致结果。

只声明实际达到的等级。若因授权或环境限制未能运行，保留复现材料并准确说明待验证项。
